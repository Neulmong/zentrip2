# 반응형 검증 기록 (spec §17.1)

> §17.1 「9종 섹션 컴포넌트 + 삽입 블록 3종을 개발 단계에서 375 / 768 / 1280px에 대해 **1회 검증하고 결과를 문서화한다**」의 이행 문서.

서버리스 환경에서 헤드리스 브라우저 검사는 비현실적이므로, spec은 매 실행 검사 대신 **개발 단계 1회 검증 + 문서화**로 보증 방식을 바꿨다. 이 파일이 그 기록이다.

## 검증 방법

**두 가지를 함께 쓴다.** 자동 실측이 수치를 재고(V-02·V-03·V-05), iframe 하네스가 테마 전환과 육안 확인을 맡는다.

```bash
npm run dev
npm run verify:responsive          # 실측 — 8화면 × 375/768/1280, 스크린샷 24장
# 로그인 후 육안 확인
open http://localhost:3000/admin/preview
```

`app/admin/preview/page.tsx` — **개발 전용** 하네스. 프로덕션에서는 404이며 §14.1 라우트 표에 없다.

- 375 / 768 / 1280px **실제 폭 iframe 3개**를 나란히 띄운다. 브레이크포인트는 뷰포트 기준이라 고정 폭 `div`로는 재현되지 않는다.
- 테마 7종을 전환한다.
- 고정 데이터는 `components/page/fixture.ts`. **경계값으로 골랐다** — 검증은 평균이 아니라 경계에서 깨진다.

| 고정 데이터가 담은 최악 조건 | 노리는 실패 |
|---|---|
| `hero.headline` 정확히 40자 · `subcopy` 80자 · 일차 서술 200자 (§17.1 상한) | 상한값에서 줄바꿈·잘림 |
| `추후 추가 예정` · `해당 없음` (§6.1) | 표기가 사라지거나 `0`으로 바뀜 |
| 공백 없는 긴 URL (`상점정보`) | 줄바꿈 실패 → 본문 가로 스크롤 |
| 항공 5열 표 | 375px에서 페이지 전체가 가로로 밀림 |
| 이미지 0장 | 이미지 없는 섹션이 깨짐 |
| `visible: false` 블록 · 참조 끊긴 `image` 블록 | 숨긴 것이 보이거나 500 |

## 컴포넌트별 적용 규칙

`components/page/` — 전 컴포넌트가 `server-only`를 import하지 않는다. 공개 페이지(서버)와 편집기 미리보기(클라이언트)가 **같은 컴포넌트를 공유**해야 하기 때문이다.

| # | 컴포넌트 | 375 | 768 / 1280 | 적용한 규칙 |
|---:|---|---|---|---|
| 1 | `hero` | `aspect-[4/3]` | `md:aspect-[21/9]` | 전면 이미지 + 스크림. 미업로드 시 **테마 그라디언트 폴백**(§9.3). 흰 글자는 스크림 위라 12:1 이상 |
| 2 | `summary` | 1열 | `sm:` 2열 | `dl` 격자, `break-words` |
| 3 | `itinerary` | 이미지 아래로 | `md:` 본문 + 240px 이미지 2열 | 슬롯이 비면 **이미지 열만** 사라지고 일차는 남는다 |
| 4 | `accommodation` | 1열 + 갤러리 2열 | `sm:` 2열 | 슬롯 상한 3장(§7.3) |
| 5 | `flight` | **자체 가로 스크롤** | 전체 표시 | `overflow-x-auto` + `min-w-[34rem]`. 페이지 본문은 밀리지 않는다 |
| 6 | `meal` | 1열 | 동일 | `whitespace-pre-line` |
| 7 | `price` | 카드 1열 | `sm:` 2열 | **총액 계산 없음**(§13.3) |
| 8 | `shop` | 1열 + 갤러리 2열 | `sm:` 2열 | 슬롯 상한 2장 |
| 9 | `apply` | 요약 1열 | `sm:` 2열 | 폼 5필드는 `data`가 아니라 **고정 컴포넌트**가 그린다(§13.1). `form` prop으로 주입 |
| 10 | `free_text` 블록 | 1열 | 동일 | 500자 상한은 **저장 시** 강제(§17.1) |
| 11 | `image` 블록 | `aspect-[16/9]` | 동일 | `product_images.id` 직접 참조. 참조가 끊기면 조용히 생략 |
| 12 | `notice` 블록 | 1열 | 동일 | 300자 상한은 저장 시 강제 |

### 공통

| 계약 | 구현 |
|---|---|
| 고정 종횡비 + `object-fit: cover` + `max-width: 100%` | `components/page/media.tsx`의 `RATIO` 3종 + `fill` + `object-cover` |
| 가로 스크롤은 자체 컨테이너 안에서만 | 항공 표만 `overflow-x-auto`. 루트에 `overflow-x-hidden` |
| `hero`는 `priority`, 나머지는 lazy | `next/image` 기본이 lazy |
| 대체 텍스트 필수 | 업로드 시 자동 채움까지 마쳐 `alt`가 비지 않는다(§7.3) |

### 대비 4.5:1 (§17.2)

**본문 텍스트에 투명도를 쓰지 않는다.** Tailwind의 `/60`은 `color-mix`로 배경을 섞어 실효 대비를 떨어뜨린다 — 어두운 글자를 밝은 배경 위에서 65%로 낮추면 **2.5:1**까지 내려가 기준 미달이다. 위계는 크기·굵기·대문자·이탤릭으로만 만든다. 투명도는 테두리·배경에만 쓴다.

| 조합 | 대비 |
|---|---|
| 본문 `--t-text` on `--t-surface` (7테마) | 12:1 이상 |
| `block-accent` 흰 글자 on `--t-primary` (6색) | 4.8:1 이상 |
| `pill-badge` `--t-text` on `--t-secondary` | 9:1 이상 |
| 히어로 흰 글자 on 스크림 | 12:1 이상 |

미입력·미운영 표기는 **색을 흐리지 않고 이탤릭으로** 구분한다.

### 완료 — 3뷰포트 실측 (2026-08-11)

**마크업 대조를 실측으로 대체했다.** 체크리스트 **V-05가 「실제 검사 없이 반응형 검사 통과를 기록만 한 건이 0건」**을 요구하므로, 마크업을 읽고 통과로 적는 것 자체가 위반이다.

```bash
npm run dev
npm run verify:responsive     # scripts/verify-responsive.mts
```

실제 Chromium(Playwright, dev 의존성)을 375 / 768 / 1280px로 띄워 **레이아웃 값을 읽는다.**

| 측정 | 판정 기준 |
|---|---|
| 문서 가로 스크롤 | `documentElement.scrollWidth ≤ clientWidth` |
| 뷰포트를 넘는 요소 | `getBoundingClientRect().right > 뷰포트 + 1px`인 요소 0개. **단 `overflow-x: auto\|scroll` 조상 안이면 정상**(자체 스크롤 컨테이너) |
| 스크롤 없이 넘치는 요소 | `scrollWidth > clientWidth`인데 `overflow-x: visible`인 요소 0개 |
| 겹침 | **자동 판정하지 않는다** — 노이즈가 크다. 전 조합 스크린샷을 남겨 육안 확인에 넘긴다 |

#### 결함이 아니었던 것 1건

스크린샷 본문 위에 어두운 원형 요소가 겹쳐 찍혀 **없는 겹침으로 보였다.** Next.js **개발 표시기**(`<nextjs-portal>`)이고 `position: fixed`라 측정에는 잡히지 않지만 `fullPage` 스크린샷에는 본문 위에 남는다. 개발 전용이며 프로덕션에는 없다(next 문서 `devIndicators`). `next.config.ts`에서 끄지 않고 **검증 스크립트에서만** CSS로 가린다 — 개발 중에는 있어야 유용하다.

#### 편집기는 데스크톱 도구다 (실패로 세지 않는다)

`/admin/products/{id}/edit`의 문서 폭은 전 뷰포트에서 **1561px**이다. §17.1이 편집기에 요구하는 것은 「편집기 **미리보기에서** 375 / 768 / 1280 뷰포트를 전환해 기획자가 직접 확인한다」이며, 편집기 자체는 좌 목록 + 중앙 편집 + 우 미리보기 3분할이고 **미리보기 칸이 선택한 뷰포트 폭을 그대로 갖는 것이 설계다.** 검증 대상은 그 iframe 안의 페이지이고, 그것은 공개 페이지와 같은 `PageRenderer`다(§9.1).

그래서 이 화면에서는 문서 가로 스크롤 대신 **수단의 존재**를 확인한다.

- [x] 미리보기 iframe 1개 이상 · 뷰포트 전환 버튼 3개 (375 / 768 / 1280 각각에서)

- [ ] **테마 7종 전환 시 대비** — 계산값은 아래 §17.2 표로 확인했으나 7종 전환 육안 확인은 `/admin/preview`에서 별도로 봐야 한다

### 완료 — 편집기 미리보기의 뷰포트 전환 (2026-08-11)

§17.1 「편집기 확인 — 편집기 미리보기에서 375 / 768 / 1280 뷰포트를 전환해 기획자가 직접 확인한다」의 구현.

`components/admin/editor/PreviewFrame.tsx` — **`src` 없는 iframe에 `createPortal`로 부모의 React 트리를 심는다.**

- 이 하네스(`/admin/preview`)와 같은 이유로 iframe이다. 고정 폭 `div`는 뷰포트 미디어 쿼리를 재현하지 못한다.
- 다른 점은 **저장 전 내용**을 보여야 한다는 것이다. `src`로 페이지를 띄우면 DB에 저장된 값밖에 못 본다. 포털은 상태가 부모에 있으므로 타이핑과 동시에 갱신되면서 폭은 진짜 뷰포트다.
- 부모의 `<style>` · `<link rel=stylesheet>`를 복제해 넣고, 개발 중 HMR이 스타일을 갈아끼우면 `MutationObserver`가 따라간다.
- 미리보기는 `/p/{slug}`와 **같은 `PageRenderer`**를 쓴다(§9.1). 신청 폼 자리에만 비활성 안내를 넣는다 — 미리보기에서 신청이 접수되면 안 된다.
- [x] `/admin/products/{id}/edit` 서버 렌더링 200 · iframe 1개 · 뷰포트 전환 버튼 3개

- [x] **확인 완료** (2026-08-11) — 3뷰포트 각각에서 iframe과 전환 버튼 3개가 존재한다. 편집기는 좌(208px) + 중앙(가변) + 우(뷰포트 폭)라 1280 미리보기는 창이 넓어야 잘리지 않는다 — 그것이 설계이며 위 「편집기는 데스크톱 도구다」 참조.

### 이 문서에서 다루지 않은 것
