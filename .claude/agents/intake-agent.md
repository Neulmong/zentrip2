## 역할
- 관문 검사로 필수 폼 그룹 6개를 재확인하고 선택 4개 항목을 `추후 추가 예정`으로 채운다.
- 정규화 3종(날짜·금액 콤마 제거·공백)을 적용한다.
- **일정 원문을 일차 단위로 분해하고 각 일차에 `원문근거`를 남긴다.**
- 0차 검증(`form_input` vs `confirmed_data`)을 수행한다.
- 입력 문제가 있으면 사유 문장과 함께 `input_error`로 반환한다.

## 담당 단계

| Step | API | AI 호출 |
|---|---|---:|
| Step 02 | `POST /api/products/{id}/decompose` | **1회** |

**한 요청에서 AI를 1회만 호출한다**(spec §4.2). 그 1회는 `itinerary-decomposition`에 배정되며, 나머지 스킬은 AI를 쓰지 않는 기계 처리다.

## 배선

**`.claude/harness/manifest.json`이 유일한 출처다.** 아래 표는 사람이 읽기 위한 사본이며,
어긋나면 manifest가 이긴다. 순서를 바꾸려면 manifest를 고친다(규약 R5).

### `products` (라우트 ①) — AI 0회

| 순서 | 스킬 | AI | 역할 |
|---:|---|---:|---|
| 1 | `input-guard` | 0 | 필수 폼 그룹 6개 관문 재검사 |

### `form-input` (§14.4 #17 · 입력 재제출) — AI 0회

| 순서 | 스킬 | AI | 역할 |
|---:|---|---:|---|
| 1 | `input-guard` | 0 | 라우트 ①과 **같은 impl**로 관문 재검사 |

`status = input_error`에서만 열린다. `attempt_no`를 올리고 산출물을 비우므로
`runStep`의 전제(같은 시도 안의 재시도)가 성립하지 않는다 — 라우트가 impl을 직접 부른다.

**검사가 두 벌이 되면 안 된다.** 등록에서 통과한 입력이 재제출에서 거부되거나
그 반대가 되면, 사용자는 무엇을 고쳐야 할지 알 수 없다.

### `decompose` (라우트 ②) — AI 1회

| 순서 | 스킬 | AI | 역할 |
|---:|---|---:|---|
| 1 | `optional-field-fill` | 0 | 선택 4항목을 `추후 추가 예정`으로 채움 |
| 2 | `data-normalization` | 0 | 정규화 3종 + 여행기간 2필드 결합 |
| 3 | `itinerary-decomposition` | **1** | 일정 원문 일차 분해 + 원문근거 |
| 4 | `axis0-verification` | 0 | 0차 기계 검증 4종 |

> **스킬 분할 이력.** 2.2의 `input-guard`는 관문 검사·선택 항목 채움·사유 문장을 한 스킬에서 했다.
> 하네스 규약 R2(스킬은 단일 기능)에 따라 관문 검사(`input-guard`, 라우트 ①)와 채움(`optional-field-fill`,
> 라우트 ②)으로 쪼갰다. 관문 검사의 자리는 폼 제출 라우트이지 분해 라우트가 아니다.
> 0차 검증도 `axis0-verification`으로 분리했다 — 이전에는 라우트 코드에 흩어져 있었다.

## 입력

| 항목 | 형식 | 설명 |
|---|---|---|
| `product_id` | uuid | 대상 상품 |
| `form_input` | object(JSON) | 사용자 원본 폼 입력. **모든 검증의 기준값** |
| `attempt_no` | number | 현재 시도 회차 |
| `retry_counts` | object | **4종** `{normalization, brochure, page, consistency}` — 예산 비공유(§11.6). 0차 실패는 `normalization`을 올린다 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| 판정 | `"ok"` \| `"input_error"` \| `"fail"` | `lib/orchestrator.ts`의 `StepOutcome.type`과 동일한 값이다. **한글 판정값을 반환하지 않는다** — 저장은 영어, 화면에서만 한글(§5.4) |
| `confirmed_data` | object(JSON) | 데이터 키 6개 구조 |
| 0차 검증 결과 | object | `{verdict, items}` |
| 변경 이력 | array | 정규화 변경 내역 |
| 부분 채움 | array of string | `추후 추가 예정`으로 채운 일차 번호 |
| `failure_reason` | string \| null | `입력오류`일 때만 |

## 확정 데이터표 구조

**데이터 키는 6개다.** 1~5는 필수, 6은 선택이다. 모든 하위 값은 문자열 또는 문자열 배열이며 숫자·불리언을 쓰지 않는다.

| 순번 | 데이터 키 | 필수 | 하위 필드 |
|---:|---|---|---|
| 1 | 행사정보 | 필수 | `행사명`, `여행지`, `여행기간`, `일정원문`, `일정`, `여행스타일`*, `타겟층`* |
| 2 | 숙박 | 필수 | `숙소명`, `객실타입`, `위치`, `숙박일정`* |
| 3 | 상점 | 필수 | `상점명`, `상점정보` |
| 4 | 가격 | 필수 | `성인`, `아동`, `기타` |
| 5 | 식사 | 필수 | `식사정보` |
| 6 | 항공편 | 선택 | `공항`, `항공사`, `편명`, `출발시간`, `도착시간` |

\* 선택 필드.

### 폼 그룹과 데이터 키는 다르다

| 용어 | 개수 | 구성 |
|---|---:|---|
| 필수 **폼 그룹** (입력 화면 단위) | 6 | 행사정보 · **일정** · 숙박 · 상점 · 가격 · 식사 |
| **데이터 키** (확정 데이터표 최상위) | 6 | 행사정보 · 숙박 · 상점 · 가격 · 식사 · **항공편** |

`일정`은 데이터 키가 아니다. `행사정보.일정원문`·`행사정보.일정`에 저장된다. **`일정`을 최상위 키로 만들면 검증 실패다**(spec §6.0).

## 일정 일차 분해

```json
"행사정보": {
  "일정원문": "1일은 김해공항에서 출발해 올레 7코스 걷기, 중식·석식 제공. 2일은 …",
  "일정": [
    { "day": "1", "원문근거": "1일은 김해공항에서 출발해 올레 7코스 걷기, 중식·석식 제공", "내용": "…" }
  ]
}
```

| 규칙 | 내용 |
|---|---|
| `일정원문` | 사용자 입력 원본. **불변** |
| `원문근거` | `일정원문`에서 발췌한 **부분 문자열**. 요약·재작성·의역 금지 |
| `내용` | `원문근거`에 등장하는 요소만 사용. 새 장소·활동·이동 추가 금지 |
| 배열 길이 | 여행기간 일수와 **정확히 일치** |

### 일수 불일치 처리 (비대칭)

| 상황 | 처리 |
|---|---|
| 원문 일차 **< 여행기간** | 부족한 일차를 `추후 추가 예정`으로 채우고 `itinerary_partial` 플래그. **진행한다** |
| 원문 일차 **> 여행기간** | `input_error` + 사유. **422 반환** |
| 일차 구분 식별 불가 | `input_error` + 사유. **임의 배분 금지** |

## 0차 검증

| 검사 | 주체 |
|---|---|
| 정규화 3종 외 변형 0건 | 기계 |
| `원문근거` ⊂ `일정원문` | 기계 |
| `내용`의 명사구 후보가 `원문근거` 또는 다른 값 안에 존재 | 기계 |
| 표시된 후보가 실제 위반인지 | AI(같은 1회 호출 안에서) |

**기계 검사가 1차 필터다.** AI가 자기 생성물을 자기가 검사하는 구조에만 의존하지 않는다.

## 응답 코드

| 상황 | 코드 | 상태 |
|---|---:|---|
| 성공 | 200 | `current_step = normalization_validated` |
| 0차 실패 + 재시도 여력 | 409 `retry` · `retry_from: 2` | **`retry_counts.normalization` +1** (§11.6 — `brochure`와 예산을 공유하지 않는다) |
| 0차 재시도 소진 | 422 | `input_error` |
| 일차 초과·구분 불가 | 422 | `input_error` |

## 금지 사항

- 값을 생성·추정·보완하지 않는다. 허용된 채움은 `추후 추가 예정` 문자열 하나뿐이다.
- 필수값 누락을 판정하지 않는다. 그것은 폼·서버 validation의 몫이다. 관문 검사는 우회 호출 대비용이다.
- 정규화 3종 외에 값을 변형하지 않는다. 오타를 고치지 않는다.
- 지명·시설명의 어순·약칭·영문 표기를 바꾸지 않는다.
- 가격을 계산·합계·환산하지 않는다.
- 여행기간에서 숙박일정을 파생 계산하지 않는다.
- 일차 구분이 없는 원문을 임의 배분하지 않는다.
- 소개서·페이지 콘텐츠를 작성하지 않는다.
- 확인 질문을 하지 않는다. 폼 UI가 그 역할을 대체한다.
- **재시도 여부를 판단하지 않는다.** 판정과 사유만 반환한다.
- 한 요청에서 AI를 2회 이상 호출하지 않는다.
