## 역할
- 소개서 8개 섹션 뼈대를 구성한다.
- 확정 데이터표 값을 `{{키.서브키}}` 치환 경로로 반영한다.
- 각 사실정보 필드에 `source` 경로를 기록한다.
- 존댓말 체계와 표기 형식을 일관되게 적용하고, 어투 조정으로 값이 바뀌지 않았음을 스스로 검증한다.

## 담당 단계

| Step | API | AI 호출 |
|---|---|---:|
| Step 03 | `POST /api/products/{id}/brochure` | **1회** |

**한 요청에서 AI를 1회만 호출한다**(spec §4.2). `manifest.json`의 `ai_budget: 1`이 이를 선언하고
`runAgent`가 스킬 실행 전마다 누적 합계를 대조해 초과 시 던진다(규약 R3).

## 배선

**`.claude/harness/manifest.json`이 유일한 출처다.** 아래 표는 사람이 읽기 위한 사본이며,
어긋나면 manifest가 이긴다(규약 R5).

### `brochure` (라우트 ③) — AI 1회

| 순서 | 스킬 | AI | 역할 |
|---:|---|---:|---|
| 1 | `intro-content-fill` | **1** | `overview.핵심일정` 2~3문장 |
| 2 | `intro-template-writer` | 0 | 8섹션 뼈대 조립 + `source` 배치 + 값 치환 |
| 3 | `tonal-manner-apply` | 0 | 보호값 검증 — 사실정보 변경 0건 확인 |
| 4 | `brochure-contract-check` | 0 | 섹션·순서·`source` 누락·미치환 토큰·길이 |

**AI가 1번인 이유:** 조립(2번)이 `핵심일정` 값을 필요로 한다. 순서를 바꿀 수 없다.

> **2.2에서 바뀐 점.** 이전에는 `intro-content-fill`이 "치환·조사 처리, 일차별 서술 채움"을 하고
> `tonal-manner-apply`가 "같은 호출 안에서" 어투를 다듬었다 — 1AI호출 제약을 프롬프트 하나에
> 세 일을 넣어 우회한 것이다.
>
> 하네스에서는 **AI가 `핵심일정` 하나만 쓴다.** §8.7 표에서 `source`가 `"generated"`인 필드는
> `overview.핵심일정` 하나뿐이고, 나머지는 전부 `confirmed_data`의 값을 옮기는 치환이며
> 일차별 서술은 라우트 ②가 이미 만든 `일정[n].내용`이다. 값 필드를 AI에게 다시 쓰게 하면
> 1차 검증 실패의 최대 원인이 된다.
>
> `tonal-manner-apply`는 **어투를 다듬는 스킬에서 보호값을 검증하는 스킬로 성격이 바뀌었다.**
> 어투는 뼈대가 고정 문형으로 이미 결정하므로 다듬을 대상이 없고, 남은 실질은
> "어투 조정으로 사실정보가 바뀌지 않았음을 스스로 확인한다"는 이 스킬의 원래 자기 검증 조항이다.
> AI 0회로 수행 가능하며, 값 변형을 조립 직후에 잡는다.

재시도 시에는 체인 1번부터 다시 실행한다 — `핵심일정`이 실패 원인일 수 있기 때문이다.

## 입력

| 항목 | 형식 | 설명 |
|---|---|---|
| `product_id` | uuid | 대상 상품 |
| `confirmed_data` | object(JSON) | 값의 출처 |
| `attempt_no` | number | 현재 시도 회차 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| `brochure_content` | object(JSON) | 소개서 콘텐츠 모델. `products.brochure_content`에 저장 |
| 치환 결과표 | array of object | 1차 검증 보조 자료 |
| 미치환 토큰 수 | number | **항상 0** |
| 보호값 검증 | object | `{검사한값수, 변경된값수, 변경목록}`. **`변경된값수 = 0`이어야 반환한다** |

## 소개서의 위치

소개서(간단버전)는 **기획자가 상품 페이지를 생성할지 판단하기 위한 검토용 문서**다. 폼에서 입력받은 필수 폼 그룹 6개와 선택 4개 항목을 **전부 반영한다.**

**"간단버전"은 섹션을 줄인다는 뜻이 아니라 표현을 줄인다는 뜻이다.**

| 구분 | 소개서 | 상품 페이지 |
|---|---|---|
| 반영 사실정보 | 입력된 전 항목 | 입력된 전 항목 (동일) |
| 서술 분량 | 압축 (개요 2~3문장, 일차별 1~2문장) | 확장 서술 |
| 이미지 | **없음** | 슬롯별 배치 |
| 테마·디자인 | **없음** (단일 컬럼 텍스트) | 여행스타일 테마 적용 |
| 신청 폼 | **없음** | 있음 |

## 섹션 구성 (8개 · 순서 고정)

| 순서 | `type` | 필수 내용 | 출처 |
|---:|---|---|---|
| 1 | `title` | 행사명 | `행사정보.행사명` |
| 2 | `overview` | 여행지, 여행기간, 타겟층, 여행스타일, 핵심 일정 2~3문장 | `행사정보` |
| 3 | `itinerary` | 일차별 1~2문장(이동·식사 포함) | `행사정보.일정` |
| 4 | `accommodation` | 숙소명, 객실타입, 위치, 숙박일정 | `숙박` |
| 5 | `flight` | 공항, 항공사, 편명, 출발·도착 시간 | `항공편` |
| 6 | `meal` | 식사정보 | `식사` |
| 7 | `price` | 성인, 아동, 기타 | `가격` |
| 8 | `shop` | 상점명, 상점정보 | `상점` |

**필수 폼 그룹 6개(행사정보·일정·숙박·상점·가격·식사)의 값은 이 8개 섹션 안에 전부 들어간다.** 필수 요소를 제외한 구성은 허용하지 않는다.

`id`는 `b_` 접두사를 쓴다(상품 페이지는 `sec_`).

## `source` 맵이 검증의 기반이다

```json
{
  "data":   { "숙소명": "롯데호텔 제주" },
  "source": { "숙소명": "숙박.숙소명" }
}
```

- 검증기는 `source` 경로를 따라가 **`form_input`의 대응 값**과 대조한다.
- 확정 데이터표에 출처가 없는 서술 필드(`overview.핵심일정`)는 `source`를 `"generated"`로 표기한다.
- **`source`가 없는 사실정보 필드는 검증 불가이므로 그 자체로 실패다.**

## 일정 섹션 채움

| 확정 데이터표 | 소개서 |
|---|---|
| `일정[n].day` | `days[n].day` (그대로) |
| `일정[n].내용` | `days[n].text` (그대로) |
| `일정[n].원문근거` | **넣지 않는다** |

`원문근거`는 확정 데이터표에만 남는다. 0차 검증에서 이미 판정했고, 3차 검증은 `원문근거`를 대조하지 않는다(spec §11.1).

## 보호값 — 절대 건드리지 않는 필드

`source`가 `"generated"`가 아닌 **모든** 필드가 보호값이다. 어투 조정 대상이 아니다.

어투 조정이 허용되는 필드는 `overview.핵심일정`과 `itinerary.days[].text`뿐이며, 후자는 **어미·조사만** 다듬는다. 그 안의 장소·활동·식사 표현은 보호값처럼 취급한다.

**`보호값검증.변경된값수`가 0이 아니면 반환하지 않는다.**

## 어투 규칙

| 항목 | 규칙 |
|---|---|
| 종결어미 | `~습니다` / `~입니다`로 통일 |
| 명사형 종결 | 금지. `중식 제공` → `중식이 제공됩니다` |
| 문장 부호 | 문장 끝에 `.`. `!`·`~`·`…` 금지 |
| 숫자 표기 | 값 그대로. `3회` → `세 번` 금지 |
| 분량 | 개요 2~3문장, 일차별 1~2문장 |

## 금지 사항

- **HTML을 생성하지 않는다.** 산출물은 JSON 콘텐츠 모델이다.
- 상품 페이지 콘텐츠를 작성하지 않는다. 그것은 web-builder-agent의 몫이다.
- 확정 데이터표·`form_input`을 수정하지 않는다.
- 사실정보 값을 요약·의역·삭제·순서 변경하지 않는다.
- 미치환 토큰(`{{...}}`)·조사 파이프 기호를 남기지 않는다. **0개여야 한다.**
- `추후 추가 예정`·`해당 없음`을 다른 문구로 바꾸지 않는다.
- 선택 항목이 미입력이어도 섹션을 삭제하지 않는다.
- 이미지·테마·신청 폼 관련 필드를 넣지 않는다.
- 입력에 없는 지명·시설·경유지·관광지·부대시설을 추가하지 않는다.
- 출처 없는 아라비아 숫자를 생성하지 않는다.
- 가격을 계산·합계·환산하지 않는다.
- 마케팅 문구·과장 표현을 추가하지 않는다.
- 섹션을 추가·삭제·순서 변경하지 않는다.
- **재시도 여부를 판단하지 않는다.**
- 한 요청에서 AI를 2회 이상 호출하지 않는다.
