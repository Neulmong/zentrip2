## 단일 기능

`brochure_content`의 **구조**를 검사한다. 사실정보의 값이 맞는지는 보지 않는다 — 그건 1차 검증(`fact-check`)의 일이다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `content-writer-agent` · `brochure` 체인 4번(마지막) · AI 0회 ·
`impl: pipeline/brochure#checkBrochure`.

## 입력

| 항목 | 형식 | 설명 |
|---|---|---|
| `brochure_content` | object | 조립이 끝난 소개서 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| `위반사유` | array of string | 사람이 읽을 사유 문장. **0건이면 통과** |

## 검사 4종

| # | 검사 | 근거 |
|---:|---|---|
| 1 | 섹션이 정확히 8개이고 `id`·순서가 `BROCHURE_SECTION_IDS`와 일치 | §8.7 |
| 2 | 사실정보 필드에 `source` 누락 0건 | §8.8 |
| 3 | 미치환 토큰 0건 — `{{`·`}}`·조사 파이프 기호가 최종 출력에 남지 않는다 | §8.8 |
| 4 | 길이 계약 위반 0건 | §17.1 |

### 섹션 8개

제목 · 개요 · 일정 · 숙박 · 항공 · 식사 · 가격 · 제휴상점. 접두사는 `b_`이며 순서는 고정이다.

`visible`·`locked`·`order`를 검사하지 않는다 — 소개서는 편집 대상이 아니라 읽기 전용 검토 문서다.

### `source` 누락은 그 자체로 실패다

값이 맞아도 `source`가 없으면 실패다(§8.8). 검증이 따라갈 경로가 없는 사실정보는 검증 불가능한 주장이기 때문이다.

## 판정 규칙

- 사유를 **모아서** 반환한다. 첫 위반에서 멈추지 않는다.
- 사유 문장은 위반 위치를 포함한다. `"개요 섹션의 핵심일정에 source가 없습니다"` 형태다.
- **재시도 여부를 판단하지 않는다.** 사유만 반환한다(R7).

## 금지 사항

- AI를 호출하지 않는다.
- `brochure_content`를 수정하지 않는다. 위반을 자동 교정하지 않는다.
- 사실정보의 **값**이 맞는지 판정하지 않는다 — `fact-check`의 영역이다.
- 편집 시점 길이 계약 6종을 생성 시점에 적용하지 않는다(§17.1 — 생성은 4종).

## 하네스 계약

`asserts`: 반환값은 문자열 배열이어야 한다(0건은 `[]`).
