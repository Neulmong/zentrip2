## 목적
- 소개서 전체를 존댓말로 통일하고 표기 형식을 맞춘다.
- 어투를 다듬는 과정에서 **사실정보 값이 단 하나도 바뀌지 않았음**을 스스로 검증한다.

## 실행 조건
- 호출 주체: content-writer-agent (workflow Step 03의 **세 번째이자 마지막** 스킬)
- 선행 조건: `intro-content-fill`이 반환한 치환 완료 소개서가 존재하고 `미치환_토큰수 = 0`
- 실행 시점: 소개서 생성 1회당 1회, 가장 마지막
- AI 호출: `intro-content-fill`과 같은 AI 호출 1회 안의 마지막 단계로 실행한다. **별도 호출을 추가하지 않는다**(spec §4.2)
- 실행하지 않는 경우: 상품 페이지 단계(Step 05) — 페이지 문장은 `web-content-structure-gen`이 담당한다

## 입력

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| 치환된 소개서 | object(JSON) | 필수 | `intro-content-fill` 출력 |
| 보호값 목록 | array of object | 필수 | `{경로, 값}` — `source`가 `"generated"`가 아닌 모든 필드 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| 소개서 | object(JSON) | `brochure_content` 최종본 |
| 보호값 검증 | object | `{검사한값수, 변경된값수, 변경목록}` |
| 어투 적용 이력 | array of object | `{경로, 이전, 이후}` — 서술 문장에 적용한 변경 |

```json
{
  "소개서": { "schema_version": "1.0", "sections": [ "…" ] },
  "보호값검증": {
    "검사한값수": 21,
    "변경된값수": 0,
    "변경목록": []
  },
  "어투적용이력": [
    { "경로": "b_itinerary.data.days[0].text",
      "이전": "김해공항에서 출발해 올레 7코스를 걷는다. 중식과 석식 제공.",
      "이후": "김해공항에서 출발해 올레 7코스를 걷습니다. 중식과 석식이 제공됩니다." }
  ]
}
```

## 산출물
- 파일 산출물 없음. 반환값이 `products.brochure_content`에 저장된다.
- 전달 대상: content-writer-agent → 서버 라우트가 DB에 저장 → 로그 `brochure_generated`
- **`보호값검증.변경된값수`가 0이 아니면 그 자체로 실패**다. content-writer-agent는 이 값을 확인하고 0이 아니면 반환하지 않는다.

## 보호값 — 절대 건드리지 않는 필드

`source`가 `"generated"`가 아닌 **모든** 필드가 보호값이다. 어투 조정 대상이 아니다.

| 섹션 | 보호값 |
|---|---|
| `title` | `text` |
| `overview` | `여행지`, `여행기간`, `타겟층`, `여행스타일` |
| `itinerary` | `days[].day` |
| `accommodation` | `숙소명`, `객실타입`, `위치`, `숙박일정` |
| `flight` | `공항`, `항공사`, `편명`, `출발시간`, `도착시간` |
| `meal` | `식사정보` |
| `price` | `성인`, `아동`, `기타` |
| `shop` | `상점명`, `상점정보` |

### 어투 조정이 허용되는 필드

| 필드 | 비고 |
|---|---|
| `overview.핵심일정` | `source = "generated"` |
| `itinerary.days[].text` | `내용` 값을 담지만 서술 문장이므로 어미·조사 조정 허용 |

`days[].text`는 **어미와 조사만** 다듬는다. 그 안에 등장하는 장소·활동·식사 표현은 보호값처럼 취급한다 — 바꾸면 0차 검증이 잡아낸 원문 근거 관계가 깨진다.

## 적용 규칙

| 항목 | 규칙 |
|---|---|
| 종결어미 | `~습니다` / `~입니다`로 통일. `~다`·`~함`·`~임` 금지 |
| 명사형 종결 | 금지. `중식 제공` → `중식이 제공됩니다` |
| 존칭 | 고객을 지칭할 때 `고객님`. 기획자·내부 표현은 쓰지 않는다 |
| 문장 부호 | 문장 끝에 `.` 사용. `!`·`~`·`…` 금지 |
| 목록 구분 | 값 안의 구분자(`·`, `,`)를 유지한다. 다른 기호로 바꾸지 않는다 |
| 숫자 표기 | 값 그대로. 한글 수사로 바꾸지 않는다(`3회` → `세 번` 금지) |
| 문장 길이 | 개요 2~3문장, 일차별 1~2문장(spec §8.6) |

## 금지 사항

- **보호값을 한 글자도 바꾸지 않는다.** 어순·공백·조사 포함.
- `추후 추가 예정`·`해당 없음`을 다른 문구로 바꾸지 않는다. `미정`·`추후 안내` 등으로 다듬으면 실패다.
- 사실정보를 요약·생략하지 않는다. 문장이 길다고 값을 빼면 실패다.
- 마케팅 문구·감탄·과장 표현을 추가하지 않는다(`꼭 가봐야 할`, `최고의` 등).
- 출처 없는 숫자를 만들지 않는다.
- 섹션을 추가·삭제·순서 변경하지 않는다.
- `source` 맵을 변경하지 않는다.

## 판정 규칙

- 어투 조정 후 **모든 보호값이 조정 전과 문자열 단위로 동일**해야 한다.
- `보호값검증.변경된값수 = 0`을 반드시 확인해 반환한다. 이 필드가 없으면 1차 검증 실패로 처리한다.
- 어투 조정으로 미치환 토큰이 새로 생기지 않아야 한다.
- **재시도 여부를 판단하지 않는다.** 검증 실패 시 대응은 클라이언트가 결정한다.
