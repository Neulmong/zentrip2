## 단일 기능

조립된 소개서의 **보호값이 확정 데이터표와 같은지 대조한다.** 변경 0건이어야 통과다.
값을 고치지 않는다 — 보고만 한다.

> ⚠️ **이 스킬의 성격이 바뀌었다.** 이름은 어투 적용(`tonal-manner-apply`)이지만
> **어투를 다듬지 않는다.** 뼈대(`intro-template-writer`)가 고정 문형으로 조립하므로
> 다듬을 대상이 애초에 없고, 남은 실질은 원래 이 스킬에 있던 자기 검증 조항
> —「어투 조정으로 사실정보가 바뀌지 않았음을 스스로 확인한다」— 뿐이다.
> 그 조항만 남겨 **AI 0회 기계 검사**로 만들었다. 이름은 로그·매니페스트의 참조를
> 깨지 않으려고 유지한다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `content-writer-agent` · `brochure` 체인 **3번** ·
**AI 0회** · `impl: pipeline/brochure#assertFactsUnchanged`.

조립(2번) **직후**에 온다 — 값 변형을 가장 이른 시점에 잡기 위해서다. 체인의 마지막이 아니다:
뒤에 `brochure-contract-check`(4) · `memo-leak-check`(5)가 온다.

이전 판본은 「`intro-content-fill`과 같은 AI 호출 1회 안의 마지막 단계」로 적혀 있었으나,
하네스에서는 성립하지 않는다 — `ai_budget`은 스킬 단위로 대조된다(규약 R3).

## 입력

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| 확정 데이터표 | object(JSON) | 필수 | **기준값** |
| 조립된 소개서 | object(JSON) | 필수 | `intro-template-writer` 출력 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| 위반 사유 목록 | array of string | 사람이 읽는 문장. **0건이면 통과** |

소개서를 반환하지 않는다. 값을 건드리지 않으므로 돌려줄 것이 없다.

위반이 1건이라도 있으면 `content-writer-agent`가 계약 검사 결과와 **합쳐 한 항목으로**
묶어 409 `retry`로 보낸다(카운터 `brochure`). 항목을 모아서 보여줘야 기획자가 한 번에
다 보고 고칠 수 있다.

## 보호값 — 절대 건드리지 않는 필드

`source`가 `"generated"`가 아닌 **모든** 필드가 보호값이다. 어투 조정 대상이 아니다.

| 섹션 | 보호값 |
|---|---|
| `title` | `text` |
| `overview` | `여행지`, `여행기간`, `타겟층`, `여행스타일` |
| `itinerary` | `days[].day` |
| `accommodation` | `숙소명`, `객실타입`, `위치`, `숙박일정` |
| `flight` | `공항`, `항공사`, `편명`, `출발시간`, `도착시간` |
| `meal` | `식사정보` |
| `price` | `성인`, `아동`, `기타` |
| `shop` | `상점명`, `상점정보` |

### 대조하지 않는 필드

| 필드 | 비고 |
|---|---|
| `overview.핵심일정` | `source = "generated"` — 확정 데이터표에 대응 값이 없다 |
| `itinerary.days[].text` | 서술 문장이라 문자열 동일 대조의 대상이 아니다 |

`days[].text`에 등장하는 장소·활동·식사 표현이 원문 근거를 벗어났는지는 **0차 검증**이
이미 판정했고, 창작이 섞였는지는 1차 `fact-check`가 본다. 이 스킬의 몫이 아니다.

## 뼈대가 이미 지키는 문형 (참고)

어투는 조정 대상이 아니라 `intro-template-writer`가 조립할 때 **고정 문형으로 결정한다.**
아래는 그 문형의 명세이며, 이 스킬은 검사하지 않는다. 바꾸려면
`lib/pipeline/brochure.ts#buildBrochure`와 이 표를 함께 고친다.

| 항목 | 규칙 |
|---|---|
| 종결어미 | `~습니다` / `~입니다`로 통일. `~다`·`~함`·`~임` 금지 |
| 명사형 종결 | 금지. `중식 제공` → `중식이 제공됩니다` |
| 존칭 | 고객을 지칭할 때 `고객님`. 기획자·내부 표현은 쓰지 않는다 |
| 문장 부호 | 문장 끝에 `.` 사용. `!`·`~`·`…` 금지 |
| 목록 구분 | 값 안의 구분자(`·`, `,`)를 유지한다. 다른 기호로 바꾸지 않는다 |
| 숫자 표기 | 값 그대로. 한글 수사로 바꾸지 않는다(`3회` → `세 번` 금지) |
| 문장 길이 | 개요 2~3문장, 일차별 1~2문장(spec §8.6) |

## 금지 사항

- **값을 고치지 않는다.** 위반을 발견해도 자동 교정하지 않고 보고만 한다.
- 소개서를 반환하지 않는다. 이 스킬은 읽기 전용이다.
- 재시도·상태 전이·로그를 결정하지 않는다(규약 R7).
- 검사 대상을 임의로 줄이지 않는다. 「이 필드는 어차피 같다」는 판단을 하지 않는다.

## 판정 규칙

- **모든 보호값이 확정 데이터표와 문자열 단위로 동일**해야 한다. 어순·공백·조사 포함.
- 1건이라도 다르면 실패다. 「거의 같다」는 통과가 아니다.
- 위반을 **모아서** 반환한다. 첫 위반에서 멈추지 않는다.
- `추후 추가 예정`·`해당 없음`도 보호값이다. 다른 문구로 바뀌어 있으면 실패다.
- **재시도 여부를 판단하지 않는다.** 카운터와 409는 `runStep`의 일이다(규약 R7).

## 하네스 계약

`asserts`: 반환값은 배열이어야 한다(`null`·`undefined` 금지 — 0건은 `[]`다).
각 항목은 사람이 읽을 수 있는 완결된 문장이어야 한다.
