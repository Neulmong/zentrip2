> **2.8**: `SECTION_PAIRS`(1:1 대응표)를 삭제했다. **소개서 source 경로 집합 ⊆ 페이지 source 경로 집합** + 같은 경로 값 동일 + 일정 배열 대조(일정 섹션을 **type**으로 찾는다: `itinerary`·`timeline`)로 판정한다. 아래 「섹션 대응표」는 2.7 기록이며 더는 존재 검사에 쓰지 않는다.


## 목적
- 소개서와 상품 페이지가 같은 사실정보를 담고 있는지 교차 확인한다.
- `source` 맵 누락, 두 생성 경로의 스키마 드리프트, 앞선 검증에서 빠진 필드를 잡아낸다.

> **이 검증의 성격**: 1차와 2차가 모두 통과하면 3차는 논리적으로 통과해야 한다(둘 다 `form_input`과 일치하므로). 따라서 3차는 사실정보 재확인이 목적이 아니라 **교차 검증·회귀 감지**가 목적이다(spec §11.1).

## 배선

`manifest.json`이 유일한 출처다. 요약: `validator-agent` · `validate-consistency` ·
**AI 0회** · `impl: pipeline/consistency#checkConsistency`.

- 시작 조건(재료 기준 §14.5): `status = generating` · `page_content` 존재 · **`axis_2 = pass`**
- 실행하지 않는 경우
  - **2차 검증이 실패한 경우** — 선행 실패 상태에서의 대조는 의미가 없다. 클라이언트가 이 API를 호출하지 않는다(§11.1)
  - 1차·2차 검증(`form_input` 대조) — `fact-check`가 담당한다
  - 편집 이후 — 편집분은 재검증하지 않는다(§10.4)

### AI에서 기계로 내렸다 (AI 6 → 5회)

두 콘텐츠 모델은 **같은 `source` 경로 문자열**을 쓴다. 소개서 `b_price.성인`과
페이지 `sec_price.성인`은 둘 다 `source`가 `"가격.성인"`이다. 그래서 필드 이름을
하드코딩하지 않고 **`source`를 조인 키로** 값을 맞대볼 수 있다.

이 방식이 이 축의 목적과 정확히 맞는다 — §11.1이 3차의 목적을 「사실정보 재확인이
아니라 **교차 검증·회귀 감지**」로 규정한다. `source` 맵 누락과 두 생성 경로의
스키마 드리프트는 `source`를 기준으로 봐야 드러난다.

**약해진 것이 아니라 강해졌다.** AI는 「대충 같아 보이면」 통과시키지만 여기서는
공백 정리 외의 어떤 차이도 통과하지 못한다.

### 포기한 것 하나 — 정직하게 적어 둔다

「페이지 일정에 소개서에 없던 관광지가 **새로** 등장했는가」는 의미 판정이라
기계로 환원되지 않는다. 그래서 방향을 하나만 본다:

| 방향 | 보는가 | 왜 |
|---|---|---|
| 소개서 명사구 → 페이지에 살아남았나 | **본다** | 압축 → 확장이므로 이 방향은 성립한다 |
| 페이지에만 있는 요소 → 창작인가 | **보지 않는다** | 연결어·안내 문구가 붙는 것이 정상이다. 구분하려면 의미 판정이 필요하다 |

두 번째는 **1·2차 `fact-check`가 `form_input` 기준으로 잡는다.** 기준값을 쥔
검사가 그 일의 주인이고, 3차는 애초에 기준값을 갖지 않는다(§11.1).

## 입력

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `brochure_content` | object(JSON) | 필수 | 소개서 8개 섹션 |
| `page_content` | object(JSON) | 필수 | 페이지 9개 섹션 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| 판정 | `"pass"` \| `"fail"` | 전체 판정 |

## 산출물
- 파일 산출물 없음. 판정 결과만 validator-agent에 반환한다. **AI를 호출하지 않는다.**
- 전달 대상: validator-agent → 서버 라우트
  - `pass` → `axis_3 = pass`, `verdict = pass` 확정 → `draft-registration` 실행 → `status = draft`
  - `fail` & 재시도 여력 있음 → `retry_counts.consistency` +1, **409**. 클라이언트가 Step 05부터 재호출
  - `fail` & 재시도 소진 → `axis_3 = fail`, `verdict = fail` 확정, **200 + 실패 항목**. `status = draft`가 되어 편집·책임 게시 경로가 유지된다
- 로그: `validation_3_completed`에 통과·실패 모두 기록한다.

## 섹션 대응표 (대조 기준)

| 소개서 섹션 | 페이지 섹션 | 대조 대상 값 |
|---|---|---|
| `b_title` | `sec_hero` | 행사명 |
| `b_overview` | `sec_summary` | 여행지, 여행기간, 타겟층, 여행스타일 |
| `b_itinerary` | `sec_itinerary` | **일차 수, 각 일차의 사실정보 값(장소·활동·식사)** |
| `b_accommodation` | `sec_accommodation` | **숙소 행 수**, 행마다 숙소명·객실타입·위치·숙박일정 |
| `b_flight` | `sec_flight` | 공항, 항공사, 편명, 출발·도착 시간 |
| `b_meal` | `sec_meal` | 식사정보 |
| `b_price` | `sec_price` | 성인, 아동, 기타 |
| `b_shop` | `sec_shop` | **상점 행 수**, 행마다 상점명·구분·위치·상점정보 |
| — | `sec_apply` | **제외**(`skipped`). 소개서에 대응 섹션이 없다. 단 내부의 가격·행사 정보는 `sec_price`·`sec_hero`와 일치해야 하며, 이는 **2차 검증**이 판정한다 |

### 배열 섹션 대조 방법 (`숙소들`·`상점들`)

두 콘텐츠 모델 모두 `source`에 **배열 경로 하나**(`숙박`·`상점`)만 적는다. 대조는 그 경로에
인덱스를 붙여 원소 단위로 한다 — `숙박[0].숙소명`. 이렇게 하면 **행 수가 다를 때 한쪽에만
있는 경로가 생겨** 「대응 필드 없음」으로 자동으로 잡히므로, 행 누락을 위한 별도 검사가 필요 없다.

행 순서도 값의 일부다(§7.4). 순서가 바뀌면 인덱스가 다른 원소를 가리켜 값 불일치로 잡힌다.

### 일정 섹션 대조 방법

`원문근거`는 **대조하지 않는다.** 그 필드는 `confirmed_data`에만 있고 두 콘텐츠 모델에는 없다. 대조 대상은 아래 둘이다.

| 대상 | 방법 |
|---|---|
| 일차 수 | `b_itinerary.data.days.length` == `sec_itinerary.data.days.length` |
| 일차 번호 | 같은 자리의 `day` 값이 같아야 한다 |
| 일차별 사실정보 | **소개서 `text`의 명사구가 페이지 `text`에 살아남았는가** (한 방향) |

페이지 쪽 `text`가 더 길고 문장 수가 많은 것은 정상이다.

명사구 대조에 **접두 일치**를 허용한다(0차와 같은 `NOUN_PREFIX_LEN`) — 확장하면서
「올레 7코스」가 「올레길 7코스」가 되는 정도는 정상이다. 값을 키우면 누락이
통과하고, 줄이면 정상 확장이 반려된다.

⚠️ **「소개서에 없던 요소가 페이지에 새로 등장하는 것」은 여기서 잡지 않는다.**
연결어·안내 문구가 붙는 것이 정상이라 구분하려면 의미 판정이 필요하다.
그 판정은 `form_input`을 기준값으로 쥔 **1·2차 `fact-check`의 몫**이다(§11.1).

## 허용 차이

| 허용 | 이유 |
|---|---|
| 앞뒤 공백, 내부 연속 공백 축약 | 표기 정리 |
| HTML 이스케이프 | 렌더링 처리 |
| **서술 문장의 분량·어순·문장 수 차이** | 소개서는 압축, 페이지는 확장. **설계된 차이다** |
| 연결어·안내 문구 추가 | `source = "generated"` 필드는 대조 대상이 아니다 |

## 실패로 판정하는 차이

| 실패 | 예 |
|---|---|
| 사실정보 **값** 자체가 다름 | 소개서 `120000원` ↔ 페이지 `130000원` |
| 값의 재표기·요약·부분 삭제 | 소개서 `조식 3회, 중식 2회` ↔ 페이지 `식사 포함` |
| 일차 수 불일치 | 소개서 4일 ↔ 페이지 3일 |
| 소개서에 있던 요소가 페이지에서 사라짐 | 소개서 `올레 7코스` ↔ 페이지 서술에 없음 |
| 한쪽만 `추후 추가 예정`, 다른 쪽은 공란 | 항공 섹션 |
| 한쪽에서 섹션 삭제 | 페이지에서 `flight` 섹션 제거 |
| `apply` 외 섹션을 `skipped` 처리 | 대조 회피 |

## 판정 규칙

- 대조 단위는 **`source` 경로**다. 필드 이름이 아니라 경로가 같은 값끼리 맞댄다.
- 서술 문장은 문자열 일치를 요구하지 않는다 — 명사구 생존만 본다.
- **서술 분량·어순·문장 수 차이만을 이유로 실패 판정하면 그 자체가 규칙 위반**이다.
- `skipped`는 **항상 `["apply"]`**여야 한다. 다른 섹션을 제외하면 실패다.
- 선택 항목 미입력 시 양쪽 모두 `추후 추가 예정`이어야 한다.
- 하나라도 불일치면 전체 판정은 `fail`이며, 실패 항목을 **전부** 반환한다.
- 값 불일치가 있을 때 어느 쪽이 옳은지 판단하지 않는다. **기준은 `form_input`이며 그 판정은 1·2차의 몫**이다. 이 스킬은 두 문서가 다르다는 사실만 보고한다.
- **재시도 여부를 판단하지 않는다.**
- `draft` 상태 표시 여부를 검사하지 않는다. 상태는 DB `status`가 단일 출처이며 콘텐츠 모델에 담지 않는다.
