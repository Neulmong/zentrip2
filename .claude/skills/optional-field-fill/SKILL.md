## 단일 기능

선택 항목의 미입력을 **`추후 추가 예정`** 한 가지 문자열로 채운다. 이것만 한다.

정규화는 하지 않는다 — `data-normalization`의 일이다.
관문 검사는 하지 않는다 — `input-guard`의 일이다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `intake-agent` · `decompose` 체인 1번 · AI 0회 ·
`impl: pipeline/normalize#fillOptional`.

## 입력

| 항목 | 형식 | 설명 |
|---|---|---|
| `form_input` | object | 사용자 원본 폼 입력. **불변** |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| `채움결과` | object | `form_input` 구조 그대로, 미입력 선택 항목만 치환된 사본 |
| `채운경로` | array of string | 채운 필드의 점 경로. 예 `["행사정보.타겟층", "항공편.편명"]` |

## 선택 항목 (spec §6.2.1 · 이 4개만)

| 경로 | 비고 |
|---|---|
| `행사정보.타겟층` | |
| `행사정보.여행스타일` | 미입력이면 테마는 기본값으로 간다 |
| `숙박.숙박일정` | **여행기간에서 파생 계산하지 않는다** |
| `항공편.*` | 데이터 키 6번 전체가 선택이다. 필드 단위로 채운다 |

## 판정 규칙

- 빈 문자열·공백만 있는 문자열·`undefined`·`null`을 미입력으로 본다.
- 이미 값이 있으면 건드리지 않는다. 값의 내용을 검사하지 않는다.
- `채운경로`가 비어도 정상이다. 이 스킬은 실패하지 않는다.
- **필수 항목이 미입력이어도 여기서 채우지 않는다.** 그것은 `input-guard`가 이미 막았어야 한다.
  여기까지 왔다면 채우지 않고 `채운경로`에도 넣지 않는다 — 0차 검증이 잡는다.

## 금지 사항

- `추후 추가 예정` 외의 문자열로 채우지 않는다.
- 다른 필드에서 값을 추론·파생·계산하지 않는다. 특히 `숙박.숙박일정`을 여행기간에서 계산하지 않는다.
- 필수 항목을 채우지 않는다.
- 값이 있는 필드를 덮어쓰지 않는다.
- 정규화·형식 변환을 하지 않는다.

## 하네스 계약

`asserts`: 없음. 반환 `채움결과`의 키 집합이 입력 `form_input`과 **동일**해야 한다(키 추가·삭제 0건).
