## 단일 기능

`slug` 문자열 하나를 발급한다. 페이지 조립·게시·중복 조회는 하지 않는다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `web-builder-agent` · `page` 체인 5번(마지막) · AI 0회 ·
`impl: pipeline/slug#proposeSlug`.

## 입력

| 항목 | 형식 | 설명 |
|---|---|---|
| `행사명` | string | `confirmed_data.행사정보.행사명` |
| `사용중slug` | Set of string | 이미 점유된 slug. 충돌 판정용 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| `slug` | string | `^[a-z0-9-]+$`를 만족한다 |
| `방식` | `"행사명변환"` \| `"무작위"` | 로그에 남긴다 |

## 발급 규칙

```text
IF 행사명이 영문·숫자·공백만으로 구성
  THEN 공백 → 하이픈, 소문자화 → slug 후보        방식 = "행사명변환"
ELSE
  p-{6자 base36} 발급                              방식 = "무작위"
  ← 한글이 한 글자라도 있으면 로마자 변환을 시도하지 않는다

IF 사용중slug와 충돌  THEN -2, -3 … 접미사
IF 접미사로도 못 피함  THEN null 반환
```

허용 문자는 영문 소문자·숫자·하이픈뿐이다(`SLUG_RE`). **한글 slug를 만들지 않는다** —
percent-encoding으로 읽을 수 없는 URL이 되기 때문이다.

한글 행사명은 대부분 무작위로 떨어진다. **이것이 정상 경로이고 실패가 아니다** — slug는 사람이 읽는
값이 아니며, 기획자가 편집기에서 언제든 바꿀 수 있다. 로마자 변환을 시도하지 않는 이유는 음역 규칙이
행사명의 표기를 바꾸는 일이 되어 §16.1의 값 변형 금지에 걸리기 때문이다.

`null`을 반환하면 호출자가 `409 slug_conflict`로 변환한다(§14.6). 이 스킬이 응답을 만들지 않는다.

## 판정 규칙

- `방식`을 항상 반환한다. 무작위로 떨어진 것은 로그에 남아야 추적된다.
- slug의 의미·가독성을 판정하지 않는다.
- **게시 여부와 무관하다.** 발급은 `page` 단계, 공개는 `publish` 단계다.

## 금지 사항

- AI를 호출하지 않는다.
- 대문자·공백·특수문자를 남기지 않는다. `SLUG_RE`를 반드시 통과한다.
- 행사명을 번역·음역하지 않는다.
- 충돌을 무시하고 덮어쓰지 않는다.
- `409 slug_conflict` 응답을 직접 만들지 않는다 — `null`을 반환하고 `runStep`에 맡긴다(R7).

## 하네스 계약

`asserts`: `slug`가 `null`이 아니면 `SLUG_RE`를 만족해야 한다.
