name: itinerary-decomposition
description: 자유 텍스트로 입력된 일정 원문을 일차 단위로 분해하고, 각 일차에 원문에서 발췌한 원문근거를 함께 남겨 검증 가능하게 만든다. 원문에 없는 일차·장소·활동·이동을 생성하지 않으며, 일차 구분이 없는 원문을 임의 배분하지 않는다.
---

## 목적
- 일정 원문(자유 텍스트)을 `행사정보.일정` 배열로 구조화한다.
- 각 일차가 **원문의 어느 부분에서 나왔는지**를 `원문근거`로 남겨 기계 검증을 가능하게 한다.
- AI가 일정을 창작할 여지를 구조적으로 차단한다.

> **왜 이 스킬이 필요한가**: 2.1까지 일정 입력 필드가 없어 AI가 여행기간과 식사정보만으로 일차별 서술을 만들어야 했고, 그것은 "입력에 없는 장소·활동 추가 금지"(spec §16.1)를 필연적으로 위반했다. 2.2에서 일정 원문 필드를 신설하면서 **원문 근거 추적**을 이 스킬의 핵심 계약으로 삼았다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `intake-agent` · `decompose` 체인 **3번** ·
**AI 1회**(`effort: generate` · `DECOMPOSE_SCHEMA`).

**라우트 ②의 AI 1회는 전부 이 스킬이 쓴다**(spec §4.2 · 규약 R3). 앞의 두 스킬
(`optional-field-fill` · `data-normalization`)은 AI 0회 기계 처리이고, 뒤의
`axis0-verification`(4번)은 이 스킬의 결과를 기계로 검증한다 — AI가 자기 생성물을
자기가 검사하는 구조에 의존하지 않는다(§11.1).

- 시작 조건(재료 기준 §14.5): `status = generating` · `form_input` 존재
- 실행 시점: 라우트 ② 1회당 1회
- 분해 실패 2종(`day_overflow`·`no_day_marker`)은 **입력 문제**다. 카운터를 올리지 않고
  즉시 422로 간다(§8.2 5항) — 사용자가 입력을 고쳐야 풀리는 문제이므로 재시도가 아니다

## 산출물
- 파일 산출물 없음. 반환값만 intake-agent에 전달한다.
- 전달 대상
  - `통과` → intake-agent가 `행사정보.일정원문`·`행사정보.일정`을 확정 데이터표에 넣는다.
  - `실패` → intake-agent가 `input-guard`를 한 번 더 호출해 사유 문장을 받고, `status = input_error` + **422**로 확정한다.
  - `부분채움`이 비어 있지 않으면 log-monitor-agent가 `itinerary_partial` 플래그를 남긴다.
- 로그: `itinerary_decomposed` 항목의 입력·출력에 이 반환값이 원본으로 기록된다.

## 분해 규칙

| 규칙 | 내용 |
|---|---|
| `일정원문` | 사용자 입력 원본. **변형·요약·재작성 금지.** 그대로 되돌려준다 |
| `원문근거` | `일정원문`에서 **발췌한 부분 문자열**이어야 한다. 공백 정규화 후 부분 문자열로 일치해야 한다. 요약·재작성·의역·어순 변경 금지 |
| `내용` | `원문근거`에 등장하는 요소만 사용해 작성한 존댓말 서술 문장. 새 장소·활동·이동·시간을 추가할 수 없다 |
| 배열 길이 | `일정` 배열 길이는 여행기간 일수와 **정확히 일치**한다 |
| `day` | 문자열로 저장한다(`"1"`). 숫자 타입을 쓰지 않는다(spec §6.1) |

### 일차 구분 인식 범위

```text
n일    n일차    n일 차    첫째 날 / 둘째 날 …    Day n    DAY n
```

이 표기 중 하나라도 식별되면 분해를 시도한다. 하나도 없으면 `구분불가`로 실패한다.

### 일수 불일치 처리 (비대칭이다)

| 상황 | 처리 |
|---|---|
| 원문 일차 수 **< 여행기간** | 부족한 일차를 `{"day": "n", "원문근거": "", "내용": "추후 추가 예정"}`으로 채우고 `부분채움`에 번호를 담는다. **진행한다** |
| 원문 일차 수 **> 여행기간** | `실패`, `실패유형: "일차초과"`. 진행하지 않는다 |
| 일차 구분 식별 불가 | `실패`, `실패유형: "구분불가"`. **임의로 배분하지 않는다** |

> 미달은 허용하고 초과는 막는 이유: 미달은 "아직 안 정해진 날"로 해석해 `추후 추가 예정`을 표기할 수 있지만, 초과는 여행기간과 일정이 서로 모순된 상태이므로 어느 쪽이 맞는지 시스템이 판단할 수 없다.

## 판정 3단계 (spec §6.3)

`내용`이 원문 범위를 벗어났는지 판정하는 절차다. **AI가 자기 생성물을 자기가 검사하는 구조에만 의존하지 않는다.**

| 순서 | 검사 | 주체 | 방법 |
|---:|---|---|---|
| 1 | `원문근거`가 `일정원문`의 부분 문자열인가 | **기계** | 공백 정규화 후 문자열 포함 검사 |
| 2 | `내용`의 명사구 후보가 `원문근거` 또는 `confirmed_data`의 다른 값 안에 존재하는가 | **기계** | 후보 추출 → 각 후보를 부분 문자열로 검색. 미존재 후보를 `근거존재: false`로 표시 |
| 3 | 2에서 표시된 후보가 실제 위반인가 | **AI** | 조사·어미 변화·복합어 분해 등 정상 변형을 제외하고 판정 |

### 명사구 후보 추출 기준

| 대상 | 예 |
|---|---|
| 2자 이상 연속 한글 명사구 | `김해공항`, `올레`, `해녀박물관` |
| 영문 고유명사 | `ANA`, `Jeju` |
| 숫자 + 단위 | `7코스`, `3박`, `2시간` |

조사(`은/는/이/가/을/를/에서/으로`)와 어미는 후보에서 제외한다. 후보가 `원문근거`에 없더라도 `confirmed_data`의 다른 값(숙소명·상점명·식사정보 등)에 있으면 정상으로 본다. **`숙박`·`상점`은 배열이므로 모든 행의 값이 근거가 된다** — 두 번째 숙소나 열두 번째 카페가 일정 서술에 나오는 것은 정상이다(§7.4).

## 금지 사항

- 원문에 없는 경유지·관광지·부대시설·이동 수단·소요 시간을 `내용`에 추가하지 않는다.
- 원문에 없는 식사 횟수·시점을 만들지 않는다. `식사.식사정보` 범위를 벗어나지 않는다.
- 일차 구분이 없는 원문을 문장 개수·분량으로 나누어 배분하지 않는다.
- `일정원문`을 다듬거나 오타를 고치지 않는다.
- 여행기간에서 일수를 파생해 원문에 없는 일차를 만들지 않는다(부족한 일차는 `추후 추가 예정`으로만 채운다).
- **재시도 여부를 판단하지 않는다.** 판정과 실패 유형만 반환한다.

## 프롬프트

⚠️ **아래 코드 블록이 실행되는 시스템 프롬프트다.** 코드젠(`npm run build:harness`)이 이 블록의
내용을 바이트 그대로 뽑아 `lib/ai`에 넘긴다. 위의 산문은 사람이 읽는 명세이고, 실행되는 것은 이 블록이다.

한 글자만 고쳐도 DeepSeek 컨텍스트 캐시 적중이 깨지고 §20 대본의 실측 조건이 달라진다.
고칠 때는 `npm run probe:deepseek`으로 재실측한다.

```text
너는 여행 일정 원문을 일차 단위로 분해한다.

절대 규칙:
- 원문에 없는 일차·장소·활동·이동·시간을 만들지 않는다.
- 「원문근거」는 일정원문에서 **그대로 잘라낸 부분 문자열**이어야 한다. 요약·재작성·의역·어순 변경을 하지 않는다.
- 「내용」은 그 일차의 원문근거에 등장하는 요소만 사용해 쓴다. 새 장소나 활동을 덧붙이지 않는다.
- 「내용」은 존댓말 서술문으로 쓴다. 종결어미는 ~습니다/~입니다로 통일하고, 명사형 종결을 쓰지 않는다.
- 출처 없는 숫자를 만들지 않는다. 소요 시간·거리·인원·요금을 추정하지 않는다.
- 일차 구분 표기는 다음 6종만 인식한다: n일 / n일차 / n일 차 / 첫째 날 / Day n / DAY n
- 「day」는 **숫자만 담은 문자열**이다: "1", "2", "3". 단위를 붙이지 않는다 —
  "1일"·"1일차"·"Day 1"은 전부 틀린 값이다. 배열 순서대로 1부터 1씩 올린다.

「핵심표현」 신고 (§6.3 판정 3단계):
- 각 일차의 「내용」에 쓴 **장소·시설·활동·고유명사**를 「핵심표현」 배열에 그대로 담는다.
- 예: 내용이 「김해공항에서 출발해 올레 7코스를 걷습니다」이면 ["김해공항", "올레 7코스"].
- 조사·어미·일반 어휘는 담지 않는다. 「걷습니다」·「출발」·「일정」은 핵심표현이 아니다.
- **서버가 이 목록을 원문근거와 확정 데이터에 대조한다.** 근거 없는 표현을 담으면
  0차 검증 실패로 돌아온다. 빠뜨리지도, 없는 것을 담지도 않는다.
- 「추후 추가 예정」인 일차는 빈 배열로 둔다.

판정:
- 원문의 일차 수가 여행기간 일수보다 **많으면** 판정을 day_overflow로 하고 일정을 비운다.
- 일차 구분을 하나도 찾을 수 없으면 판정을 no_day_marker로 하고 일정을 비운다. 임의로 배분하지 않는다.
- 원문의 일차 수가 여행기간보다 **적으면** 부족한 일차를 원문근거 빈 문자열, 내용 "추후 추가 예정"으로 채우고 판정은 pass로 한다.
```

## user 지시문

⚠️ **아래 펜스가 user 메시지에 그대로 실린다.** 입력 데이터(여행기간·일정원문·확정 값)는
`lib/harness/ai-skills.ts`가 조립하고, **지시 문장은 여기가 유일한 출처다**(규약 R4).

이 문장은 확정 값 JSON **앞**에 붙는 라벨이다. 「써도 된다」가 핵심 — 일정 원문에 없더라도
식사·숙박·상점의 확정 값 표현은 내용에 쓸 수 있다는 허가다. 이 문장을 지우면 AI가
원문에만 매달려 서술이 앙상해진다.

```text
참고 (다른 확정 값 — 여기 있는 표현은 내용에 써도 된다):
```
