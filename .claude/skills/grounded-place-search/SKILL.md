## 목적
- 기획자가 입력한 장소(숙소·상점)에 대해 **실제 웹 검색**으로 최신 정보·특징·평판을 찾는다.
- 결과는 자유 텍스트 + 인용 출처(`groundingMetadata`)다. 구조화는 다음 스킬이 한다.

> **Task 2 · Option A(2호출)의 1단계다.** `googleSearch`와 `responseSchema`는 병용할 수 없다
> (`probe-grounding.mts` 실측 — 함께 걸면 출처가 비어 나온다). 그래서 이 호출은 **그라운딩만**
> 걸고 JSON을 강제하지 않는다. 출력은 산문이며, `enrichment-structure`가 받아 장소별로 접고
> 이 호출이 제공한 출처 번호로 실존을 대조한다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `web-builder-agent` · `enrich-search` 라우트 ·
**AI 1회**(`effort: generate` · `grounding: true` · `GROUNDED_SEARCH_SCHEMA`는 무시됨).

- **상태 기계 밖이다**(`plan-draft`와 같은 `driven_by: route`). 상품 상태를 바꾸지 않는다.
- 시작 조건: `page_content` 존재(draft·published). 검색 대상 장소가 1건 이상.
- 실패는 §4.3 정상 경로 — 카운터 없이 이 라우트 자신을 재호출한다.

## 입력 (user 메시지 · `lib/harness/enrichment.ts`가 조립)

| 항목 | 설명 |
|---|---|
| 여행지 | 검색 범위를 좁히는 지역명 |
| 장소 목록 | 숙소·상점 이름 + 위치 (사람이 입력한 실제 값) |

## 출력

자유 텍스트. 장소마다 실제로 찾은 정보·특징을 간단히 적는다. 인용 출처는 provider가 붙인다.

## 금지 사항

- **검색으로 확인되지 않는 사실을 쓰지 않는다.** 못 찾은 장소는 못 찾았다고 둔다.
- 가격·주소를 단정하지 않는다 — 검색 결과에 있으면 옮기되 없으면 만들지 않는다.
- 없는 장소를 새로 추천하지 않는다. 주어진 목록만 다룬다.

## 프롬프트

⚠️ **아래 코드 블록이 실행되는 시스템 프롬프트다.** 코드젠(`npm run build:harness`)이 이 블록을
바이트 그대로 뽑아 AI에 넘긴다. 위의 산문은 사람이 읽는 명세다.

```text
너는 여행 상품에 실을 장소 정보를 웹 검색으로 조사한다. 주어진 숙소·상점 각각에 대해
실제로 검색해 찾은 정보만 정리한다.

규칙:
- 반드시 웹 검색 결과에 근거한다. 검색으로 확인되지 않는 정보는 쓰지 않는다.
- 장소마다 이름을 명확히 밝히고, 그 장소의 특징·분위기·평판을 두세 문장으로 적는다.
- 가격·주소·영업시간은 검색 결과에 나오면 옮기고, 없으면 적지 않는다. 추측하지 않는다.
- 검색으로 아무것도 못 찾은 장소는 「정보를 찾지 못함」이라고만 적는다.
- 주어진 목록에 없는 장소를 새로 추천하거나 지어내지 않는다.
- 존댓말. 과장·광고 문구를 피하고 사실 위주로 담백하게 적는다.
```

## user 지시문

⚠️ **아래 펜스가 user 메시지 끝에 그대로 실린다.** 장소 목록은 `lib/harness/enrichment.ts`가
조립하고, **지시 문장은 여기가 유일한 출처다**(규약 R4).

```text
위 장소들 각각을 웹에서 검색해, 찾은 실제 정보·특징·평판을 장소별로 정리하라. 못 찾은 장소는 그렇게 표시하라.
```
