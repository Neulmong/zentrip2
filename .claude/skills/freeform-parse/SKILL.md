## 단일 기능

자연어 텍스트에서 **기계로 알아볼 수 있는 것만** 뽑는다. 이것만 한다.

일차 배분은 하지 않는다 — `trip-planning`의 일이다.
검사·판정은 하지 않는다 — `draft-form-check`의 일이다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `planner-agent` · `plan-draft` 체인 **1번(맨 처음)** ·
AI 0회 · `impl: pipeline/freeform#parseFreeform`.

**체인의 처음이다.** 2번(`trip-planning`)이 이 추출 결과를 재료로 받고, 3번(`draft-form-check`)이
`장소후보`를 누락 0건 검사의 기준 목록으로 쓴다.

## 왜 AI가 아닌가

두 가지 이유가 있고, 둘째가 더 중요하다.

1. 라벨(`-항목:`)·괄호 주소(`이름 (주소)`)·`11.04~11.08` 날짜는 **규칙 치환으로 환원된다.**
   규약 R3의 기본값이 `mechanical`인 이유가 이것이다.
2. **이 추출 결과가 누락 검사의 기준 목록이다.** AI가 목록을 만들면 AI가 빠뜨린 것을
   AI의 목록으로 검사하게 되고, 검사가 죽는다. 카페 13곳 중 3곳을 AI가 흘렸을 때
   그 3곳이 기준 목록에도 없으면 「누락 0건」이 나온다.

## 입력

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| `text` | string | 필수 | 자연어 메모 원본. **불변** |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| `블록` | `{라벨, 본문}[]` | `-라벨:` 로 시작하는 줄을 경계로 자른 덩어리 |
| `날짜` | `{시작, 종료} \| null` | `11.04~11.08` · `2026-11-04` 등에서 읽은 ISO 날짜 2개 |
| `일수` | number \| null | 날짜에서 계산(§6.2.1 양끝 포함). 날짜가 없으면 `null` |
| `장소후보` | `{이름, 주소, 출처}[]` | 아래 두 규칙으로 뽑는다. `출처`는 나온 블록의 라벨 |
| `URL` | string[] | 참고 링크. 초안의 값 필드에 넣지 않는다 |

```json
{
  "블록": [
    { "라벨": "여행일정", "본문": "4박5일 (11.04~11.08)" },
    { "라벨": "숙박", "본문": "조금불편해도괜찮아 (구좌읍 김녕로1길 35-24), 고요한하루 (북선로 241)" }
  ],
  "날짜": { "시작": "2026-11-04", "종료": "2026-11-08" },
  "일수": 5,
  "장소후보": [
    { "이름": "조금불편해도괜찮아", "주소": "구좌읍 김녕로1길 35-24", "출처": "숙박" },
    { "이름": "고요한하루", "주소": "북선로 241", "출처": "숙박" },
    { "이름": "시간을담다", "주소": "구좌읍 평대7길", "출처": "카페 및 음식점" }

  "URL": ["https://www.yna.co.kr/view/AKR20260708117400056"]
```

## 추출 규칙

### 라벨 블록

줄 시작의 `-`·`·`·`*` 뒤에 오는 `라벨:` 또는 `라벨 :`을 경계로 본다. 라벨이 없는 첫 덩어리는
`라벨: ""`로 담는다 — 버리지 않는다.

### 날짜

| 표기 | 해석 |
|---|---|
| `11.04~11.08` · `11/04~11/08` | 연도 없음. **연도를 추정하지 않고** `연도미정`으로 표시한다 |
| `2026-11-04 ~ 2026-11-08` | 그대로 |
| `2026.11.04~11.08` | 앞의 연도를 뒤에도 적용한다 |

**연도가 없으면 만들지 않는다.** 「올해」·「내년」을 고르는 순간 그것은 추정이고, 여행기간은
일차 수·이미지 슬롯 수를 결정하는 값이다(§6.2.1). 연도미정이면 `날짜: null`로 두고 화면이
사람에게 날짜를 고르게 한다.

### 장소 후보 — 규칙 2종

**규칙 B(목록 블록)를 먼저 돌고, 그 다음 규칙 A(전역)를 돈다.** 먼저 등록된 쪽이
이기므로 더 정확한 해석이 남아야 한다.

#### 규칙 B — 목록 블록의 줄 하나가 장소 하나

라벨에 아래 낱말이 들어 있으면 그 블록을 장소 목록으로 본다. **확정 목록이며 구현에서
임의로 넓히지 않는다** — §6.3의 일차 구분 6종과 같은 성격이다.

```text
숙박  숙소  카페  음식점  맛집  식당  상점  가게  여행지  포인트  장소  코스  방문
```

블록의 각 줄에서 이름과 주소를 가른다.

| 줄 | 이름 | 주소 |
|---|---|---|
| `시간을담다 (구좌읍 평대7길)` | 시간을담다 | 구좌읍 평대7길 |
| `보롬창고 구좌읍 종달항길3)` | 보롬창고 | 구좌읍 종달항길3 |
| `함덕해수욕장` | 함덕해수욕장 | (없음) |
| `김녕해수욕장, 세기알` | 두 후보로 가른다 | (없음) |

**두 번째 줄이 이 규칙의 존재 이유다.** 실제 메모에 여는 괄호가 빠진 줄이 있었다.
괄호 규칙만 쓰면 그 가게가 후보에서 빠지고, 후보에서 빠지면 **누락 검사가 그 가게를
보지 않는다.** 「누락 0건」이 나오는데 실제로는 한 곳이 사라진 상태가 가장 나쁘다.

주소를 가를 때 첫 공백을 경계로 쓰므로 주소가 틀릴 수 있다. **이름을 살리는 쪽으로
가른다** — 주소는 사람이 폼에서 바로 보고 고칠 수 있지만, 이름이 후보에 없으면
검사기가 그 가게의 존재 자체를 모른다.

#### 규칙 A — 전역 `이름 (주소)`

목록 블록 밖에서도 `이름 (주소)` 패턴을 찾는다. `-행사: 제주올레걷기축제 (11.05~11.07)`의
축제명이 여기서 잡힌다. 괄호 안이 주소인지 날짜인지 설명인지 **판정하지 않는다.**

#### 공통

- 이름에서 조사·꼬리표를 떼지 않는다. **원문 그대로가 누락 검사의 기준**이므로 여기서
  손대면 초안에 온전히 들어간 값이 「누락」으로 잡힌다.
- 2자 미만·URL은 버린다. 같은 이름이 두 번 나오면 처음 것만 담는다.
- `출처`에 블록 라벨을 담는다. `trip-planning`이 분류 신호로 쓴다 — 「어느 것이 숙소이고
  어느 것이 가게인가」를 이름만으로는 알 수 없고, 기획자는 이미 블록으로 분류해 두었다.

## 금지 사항

- 값을 해석·보완·정규화하지 않는다. 주소를 완성하지 않는다.
- 연도를 추정하지 않는다.
- 장소 후보를 걸러내지 않는다. 「이건 가게가 아닌 것 같다」는 판정을 하지 않는다.
- 텍스트에 없는 항목을 만들지 않는다.
- 일차를 배분하지 않는다.

## 판정 규칙

- 추출 실패는 실패가 아니다. 아무것도 못 찾으면 빈 배열·`null`을 반환한다.
- `장소후보`가 0건이어도 체인을 멈추지 않는다 — 장소 없이 일정만 적은 메모도 유효한 입력이다.
