> **2.8**: 여행스타일 1:1 룩업을 버렸다. **AI가 hue+mood를 고르고 이 스킬은 그것을 검증·폴백한다**(`resolveThemeSpec`). 색은 OKLCH로 계산되고 대비 4종이 강제된다(§9.4). 아래 「매핑표」는 hue/mood가 아예 없을 때의 **폴백 시작점**으로만 남는다. AI **뒤**로 이동해 체인 3번이다.


## 목적
- `행사정보.여행스타일` 값을 테마 키로 매핑한다.
- 컬러 스킴·헤드라인 톤·강조 포인트 3가지 디자인 토큰을 결정한다.
- 테마의 영향 범위를 3가지로 못박아 사실정보 변경을 막는다.

## 배선

`manifest.json`이 유일한 출처다. 요약: `web-builder-agent` · `page` 체인 **1번(맨 처음)** ·
**AI 0회** · `impl: pipeline/theme#resolveTheme`.

체인의 처음이다 — 필요한 것은 `confirmed_data.행사정보.여행스타일` 하나뿐이므로 앞선 스킬의
산출물을 기다릴 이유가 없다. 결정된 테마 키는 3번(`web-content-structure-gen`)이 조립에 쓴다.

- 실행 시점: 페이지 생성 1회당 1회
- AI 0회. 매핑표 조회이므로 기계 처리다
- 실행하지 않는 경우
  - 소개서 생성(라우트 ③) — 소개서에는 테마를 적용하지 않는다(spec §8.6)
  - 편집기(`PATCH /content`) — **테마는 편집기에서 변경할 수 없다**(spec §9.4)

## 입력

| 항목 | 형식 | 필수 | 설명 |
|---|---|---|---|
| 여행스타일 | string | 필수 | `행사정보.여행스타일`. `추후 추가 예정`일 수 있다 |

## 출력

| 항목 | 형식 | 설명 |
|---|---|---|
| 테마 키 | string | `page_content.theme`에 저장될 값 |
| 컬러 스킴 | object | 4종 CSS 색상값 |
| 헤드라인 톤 | string | 헤드라인 서체·굵기·자간 프리셋 이름 |
| 강조 포인트 | string | 강조 요소의 적용 방식 |
| 폴백 여부 | boolean | `default`로 폴백했는지 |

```json
{
  "테마키": "nature",
  "컬러스킴": {
    "primary": "#2F6B4F",
    "secondary": "#A8C6A1",
    "surface": "#F4F7F2",
    "text": "#1C2B22"
  },
  "헤드라인톤": "calm-serif",
  "강조포인트": "underline-accent",
  "폴백여부": false
}
```

## 산출물
- 파일 산출물 없음. 반환값만 web-builder-agent에 전달한다.
- 전달 대상: web-builder-agent → `web-content-structure-gen`(다음 스킬). `테마키`가 `page_content.theme`에 저장된다.
- **`products` 테이블에 별도 `theme` 컬럼을 쓰지 않는다.** 2.1까지 이중 저장이었으나 동기화 규칙이 없어 2.2에서 `page_content.theme` 단일 출처로 정리했다(spec §5.1).

## 매핑표

`여행스타일` select 옵션과 테마 키는 1:1 대응한다.

| 여행스타일(표시 문자열) | 테마 키 | 헤드라인 톤 | 강조 포인트 |
|---|---|---|---|
| 자연 | `nature` | `calm-serif` | `underline-accent` |
| 휴양 | `resort` | `soft-sans` | `pill-badge` |
| 도심 | `urban` | `tight-sans` | `bar-accent` |
| 미식 | `culinary` | `warm-serif` | `dot-accent` |
| 액티비티 | `active` | `bold-sans` | `block-accent` |
| 문화·역사 | `heritage` | `classic-serif` | `rule-accent` |
| (미입력 / `추후 추가 예정`) | `default` | `neutral-sans` | `underline-accent` |

> `여행스타일`은 select이므로 자유 입력이 아니다. 표에 없는 값이 들어오면 `default`로 폴백하고 `폴백여부: true`로 반환한다.

## 적용 범위 (3가지로 한정)

| 범위 | 내용 |
|---|---|
| 컬러 스킴 | `primary`·`secondary`·`surface`·`text` 4종 CSS 색상값 |
| 헤드라인 톤 | 헤드라인의 서체·굵기·자간 프리셋 |
| 강조 포인트 | 강조 요소(밑줄·배지·바 등)의 적용 방식 |

## 금지 사항

- **섹션 구성을 바꾸지 않는다.** 테마에 따라 섹션을 추가·삭제·순서 변경하지 않는다.
- **문구를 바꾸지 않는다.** 테마에 맞춰 문장을 다듬거나 수식어를 넣지 않는다.
- **사실정보를 바꾸지 않는다.** 값에 손대지 않는다.
- 레이아웃·컴포넌트 구조를 바꾸지 않는다. 그것은 고정 컴포넌트의 책임이다(spec §2.3).
- 콘텐츠 길이 계약을 바꾸지 않는다. 테마별로 다른 상한을 쓰지 않는다(spec §17.1).
- 소개서에 테마를 적용하지 않는다.
- 대비 기준을 위반하는 색 조합을 반환하지 않는다. 본문 대비 4.5:1 이상(spec §17.2).

## 판정 규칙

- 여행스타일이 비었거나 `추후 추가 예정`이면 `default`를 반환한다. 실패로 처리하지 않는다.
- 컬러 스킴 4종이 모두 CSS 색상값으로 채워져야 한다.
- 테마로 인한 섹션·문구·사실정보 변경이 **0건**이어야 한다. 2차 검증이 이를 판정한다.
- **재시도 여부를 판단하지 않는다.**
